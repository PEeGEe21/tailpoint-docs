# Project Ownership

Tailpoint uses a hybrid project-ownership model:

- The user who creates a project is its permanent creator and always remains an Owner.
- A confirmed, connected project member can be promoted to Owner after joining.
- A project can have any number of co-owners.
- Owners can manage project settings, invitations, and member roles, including promoting or demoting other co-owners.
- Owners cannot demote themselves. Another Owner must make that change.
- Direct invitations with the Owner role are not supported; invite the person first, then promote the joined member.
- Organization administrators receive effective Owner permissions for administration but are not listed as project Owners unless they are also the creator or an Owner-role project member.

Project membership is unique per project and user. Owner-targeted notifications resolve recipients as the permanent creator plus every confirmed, connected Owner-role member.

Primary ownership transfer is not part of the current model. If transfer becomes necessary, it should be introduced as an explicit audited workflow rather than by changing the creator record directly.
